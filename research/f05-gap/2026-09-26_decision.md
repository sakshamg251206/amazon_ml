# Closing the F0.5 gap: what to implement (decision report, 2026-09-26)

**Question:** Which CPU-feasible changes raise out-of-fold macro F0.5 from 0.951 toward ≥ 0.98, within about one day, without external data?

**Answer:** The gap was mostly a **feature gap**. Our margin features were built on token-set fuzz, which cannot see an added word. The best documented team's model is two-thirds a margin on the blocker's TF-IDF score. Adding that family of features lifted our M1 from **0.9429 to 0.9590 (+0.0161, measured OOF)**. Nothing measured supports ≥ 0.98 in the time left.

Sources are in `sources/`; source NN = `sources/NN_*.md`.

## Hypotheses

- **H1 (feature gap, specifically TF-IDF margins): confirmed.** Sources 01, 02 and 05 agree, and our E-F2 measured +0.0161. The rank-1 gain feature matches source 01's.
- **H2 (neighbour distractors dominate FPs): confirmed, with a second type.** Besides "name + word, shifted number", we see *different businesses in the same building* ("indo lotus enterprises" vs "indo memorial trust"; source 08).
- **H3 (empty-address name search helps): under-determined, leaning refuted.** Source 01 measured no gain; our run failed.
- **H4 (≥ 0.98 reachable now): refuted for the time available.** Source 01 needed five versions and a GPU for embedding kNN to reach 0.9821 on validation, and its best *leaderboard* was 0.962.

## Adversarial pass

1. **Is the 0.97–0.99 benchmark comparable to our 0.951?** Only partly.
   - Validation designs differ. Source 01 fits on 200k S1 and blocks against all train S1. Source 04 used 5k S1, which inflates scores. vishwajit's repo is gone, so it cannot be re-checked.
   - So we relied on *our own* measured delta, not on their absolute levels.
2. **Could the new features hurt France?** The risk is lower than for crowding features: `rev_*` and `ctx_*` are ratios within one record's or one S1's candidates, not density counts, and source 01's v1 already used them and scored its best leaderboard (0.962).
   - Residual risk: French candidate lists are denser, so `ctx_rel_*` shift.
   - Check before submitting: France match rate and matches-per-S1 against US/India.
3. **Selection bias?** None. E-F2 changed features only, with the same folds and parameters, and was compared to the matching baseline (M1 + expected-F, 0.9429).
4. **Did anything contradict the plan?** Yes, two things:
   - Source 01 found expected-F no better than a threshold. We measured +0.001, so we keep it, but it is marginal.
   - Source 01's "no gain" on empty-address search made us drop E-B5 despite our miss audit.
